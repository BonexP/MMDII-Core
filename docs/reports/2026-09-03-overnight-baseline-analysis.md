### 2.4 评价口径

- 训练目标为焊缝级三个独立 sigmoid 标签，损失为训练折估计的加权 BCE；
- OOF 预测表示该焊缝未参与对应模型训练，优先使用它评价泛化；
- PR-AUC 使用正例比例作为随机排序参考；
- 表中 `F1/Precision/Recall` 使用现有实现的固定阈值 `0.5`，不是经过 OOF 调优的生产阈值；
- 本报告额外计算了 pooled OOF 指标，即先合并五折的 101 行预测再计算，避免把没有正例的折硬塞进均值；
- pooled OOF AP 跨越五个不同折模型，若各折概率标度不一致，跨折排序也会受校准影响；因此它比当前逐折宏平均更完整，但仍应结合逐折值和后续重复实验判断；
- 只有一个随机种子（`seed=7`），没有重复运行，因此这是一次可复现的基线实验，不是最终置信区间。

## 3. 每个实验究竟做了什么

所有实验共享同一 release、同一图片组分组折、同一目标、同一归一化原则、同一 OOF 输出格式和同一训练配置（20 epochs、AdamW、学习率 `0.001`、weight decay `0.0001`）。这样比较时主要改变模型路线，而不是数据划分。

| 编号 | 输出目录 | 具体实施 | 研究问题 |
|---|---|---|---|
| **B0** | `b0-statistical` | 每个焊缝的 `af/sf/axialf` 信号按通道提取均值、标准差、RMS、最小值、最大值、峰峰值；每折只在训练折拟合 one-vs-rest Logistic Regression | 不使用深度网络时，手工统计量能达到什么水平？ |
| **E0** | `e0-full-signal` | 每条完整信号重采样到固定长度 `4096`，输入 ModernTCN-small，再用单个焊缝级 head 输出三标签 | 保留整段时间上下文是否比窗口化好？ |
| **E1a** | `e1a-mean` | 按秒重采样到 `5400 Hz`，窗口 `2 s`、步长 `1 s`；每个窗口经过 ModernTCN-small，窗口 embedding 做 masked mean | 窗口化本身是否有帮助？ |
| **E1b-max** | `e1b-max` | 与 E1a 相同，但焊缝结果取所有有效窗口的逐维 max | “一个异常窗口即可代表焊缝”的假设是否有效？ |
| **E1b-topk** | `e1b-topk-mean` | 与 E1a 相同，取每个维度 top-3 窗口的均值 | 少量高响应窗口是否比全窗口平均更稳定？ |
| **E1c** | `e1c-gated-attention` | 与 E1a 相同，使用按目标类别独立的 gated attention 对窗口加权，再输出焊缝级三标签 | 不同缺陷是否需要关注不同时间窗口？ |

其中 ModernTCN-small 是轻量的 pointwise 投影、深度可分离大核时间卷积、归一化、残差和跨通道混合；MIL 的窗口权重只用于聚合，不等价于已经验证的缺陷起止位置。

## 6. 结果解释与进一步推理

### 6.1 B0 为什么整体胜出

B0 没有窗口级深度表达能力，却在 pooled AP、微 F1、Brier、flash F1 和 tunnel AP 上领先。
这说明当前信号中的一部分判别信息可能已经存在于幅值、波动性和峰峰值等低维统计量中。
更深的模型在只有 101 条焊缝、每图组仅少量独立样本时，容易把训练折中的模式拟合得更充分，
却不能稳定转移到新的图片组。

这不是“深度学习没有用”的证明，而是一个必须保留的下界：后续模型必须至少与 B0 比较，
并说明它改善的是哪一个目标、哪一种运营代价或哪一种可解释性，而不是只展示深度模型自身的分数。

### 6.2 E1c 的真实价值与边界

E1c 的宏 F1 `0.683` 和 exact match `0.485` 是本批次最高，且 blur 的 Recall/F1 最高。
这说明按缺陷类别对窗口赋权，可能比 max 或 top-k 更能处理“缺陷信号分散在多个窗口”的情况。

但 E1c 的宏 AP 只有 `0.634`，低于 B0 的 `0.785`；flash 的 AP 也低于 B0，tunnel 的 AP 更不稳定。
因此 attention 目前应被解释为**一种焊缝级聚合机制和候选窗口排序信号**，不能称为已经定位了隧道缺陷的开始位置。

### 6.3 为什么不能把 flash 的高分当作成功

`flash` 的正例比例为 91.1%，随机排序 AP 基准就是 0.911。E1c 的 AP `0.907` 实际略低于该基准，
而 B0 的 `0.989` 才显示出较明确的排序增益。与此同时，全部预测为正的 F1 是 `0.953`，高于所有深度模型的 flash F1。
所以后续报告必须同时给出类别比例基准，不能只报告宏平均或单一 F1。

### 6.4 tunnel 结论只能是“有信号但证据不足”

三种窗口聚合的 tunnel Recall 都在 `0.5-0.6` 附近，但 AP 只有 `0.213-0.340`；B0 达到 `0.617`。
10 个正例来自 3 个图片组，且两个验证折没有正例。此结果无法支持稳定的 tunnel 检测能力结论，
更不能支持时间定位结论。要推进 tunnel，优先级应是增加独立实验组/正例，而不是先堆更大的网络。

### 6.5 窗口化是否已经被证明有用

尚未被证明。E1a 的 AP `0.700` 高于 E0 的 `0.690`，但低于 B0，且 E1a 的 pooled F1 低于 E0。
这更像是一个值得继续控制变量复验的弱信号，而不是明确胜负。窗口法的工程价值仍然存在：
它为将来弱定位、候选区间审查和 MIL 聚合提供接口；但窗口数量增加不等于独立样本数量增加，
有效独立样本仍主要由 24 个图片组决定。

### 6.6 本批次有哪些尚未解决的混杂因素

- 只有一个 seed，无法估计初始化敏感性；
- 深度模型都固定 20 epochs，没有 early stopping 或折内超参数选择；
- 阈值统一为 0.5，没有基于训练折的阈值校准；
- B0 与深度模型的容量、正则化和优化方式不同，不能把分数差异完全归因于“深度/非深度”；
- `pore` 被排除，3 个无正式缺陷样本太少，正常类能力无法独立评价；
- 所有窗口都继承焊缝级标签，模型学到的是“该焊缝有过该缺陷”，不是“这个窗口一定有该缺陷”。

## 7. 当前阶段判定

研究路线现在位于：

```text
Dataset v0.2 契约
  -> 无泄漏分组折与窗口加载器
  -> CUDA 环境验证
  -> E1c 单模型冒烟
  -> 六组真实数据基线矩阵 [已完成]
  -> 结果审计与模型选择 [当前]
  -> 受控复验/阈值与稳定性分析
  -> 决定是否实现 PatchTST-style encoder
```

本批次达到“训练闭环和基线矩阵可复现”这一阶段目标，但还没有达到“选定最终模型”或
“可用于生产缺陷判定”的阶段。

## 8. 下一步建议（按优先级）

1. **先冻结并归档本批次结果。** 保留压缩包、代码提交、release ID 和本报告，不覆盖原始输出。
2. **补一个统一的类别比例基线和阈值报告。** 对每个目标报告随机 AP、全正 F1，并在训练折内选择阈值后只在 OOF 上评估。
3. **做稳定性复验。** 至少使用 3 个 seed；仍按图片组分折，报告 pooled OOF 均值、标准差和每个目标的结果。
4. **把 B0 与 E1c 作为两个候选基线。** B0 作为强而简单的参考，E1c 作为具有窗口排序能力的候选；先分析误例，再决定网络升级。
5. **若资源允许，优先增加 tunnel 独立正例和正常样本。** 这比先增加网络深度更能提升结论可信度。
6. **最后再做 PatchTST-style 替换实验。** 保持同一 release、fold、seed、窗口和输出协议，只替换 encoder；不能同时改变聚合器和数据处理。
